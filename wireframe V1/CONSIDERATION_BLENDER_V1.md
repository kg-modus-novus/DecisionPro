# Consideration Blender — Wireframe V1 Plan

Status: directional visual hypothesis (synthetic demo imagery)
Provenance: Director-directed refinement of Focus Chooser + Requirements Assessment interpretation
Authority: not a Director-approved policy specification

## Product shift

DecisionPro V1 evidence pages remain available as deep rooms. The primary legislative interaction becomes:

1. Scan focus tabs (multiple concurrent lenses)
2. Send findings into a Consideration Blender
3. Weigh competing focuses visually
4. Examine win-win-win option packs
5. Export a Consideration Brief

## Focus tabs (scanable lenses)

- Budget pressure
- Constituent care / outcomes
- Access / rural care
- MCO accountability
- District story
- Bill readiness

Tabs are parallel, not mutually exclusive. Selected findings become Blender inputs.

## Consideration Blender

- **Left rail:** incoming findings as metric chips (focus tag, magnitude, confidence/freshness, constituency relevance)
- **Center competition surface:**
  - 4-quadrant for pairwise tensions (e.g. Budget constraints vs Constituent care)
  - Radar for 3+ active focuses
- **Visible weights:** legislator can rebalance emphasis; suggestions recalculate visibly
- **Right / lower:** Win-Win-Win Option Packs — innovative combinations to examine, never prescriptions

## Question spine (inside Blender)

Results → Path → Trajectory → Law/Pending → Trust → Action

## Trust rules in Blender

Gappy, lagged, or incentive-skewed sources shrink visual weight or show a trust flag. Action/export warns if Trust stage is incomplete.
